## 3. Workflow

1. **Register / sign in** — use `demo@shopflow-demo.pulsetrace` if created above.
2. **Open project** — *ShopFlow (Demonstration)*.
3. **Services** — API Gateway, Auth, Payment, Inventory, Database with dependencies.
4. **Logs** — confirm `shopflow_incident.jsonl` batch imported.
5. **Run analysis** — project → Analysis → Run (anomalies + clusters from real engines).
6. **Review anomalies** — error spike aligned with DB and gateway degradation.
7. **Correlate incident** — Incidents → Correlate; open new incident.
8. **Timeline / evidence** — deployment near window, upstream DB errors, gateway 502s.
9. **RCA** — Investigate; review ranked candidates, supporting and contradicting evidence.
10. **Export** — Markdown investigation report.

## Scenario narrative (for interviews)

1. Steady traffic across five services.
2. Database pool exhaustion begins ~2h45m before “now”.
3. Payment and Inventory errors propagate.
4. API Gateway deployment v2.4.1 occurs ~1h20m before “now” (some errors pre-date deploy).
5. Gateway timeouts and circuit-open events intensify.
6. RCA should weigh **upstream database failure** against **deployment regression** using evidence weights, not LLM guesses.
